# EduPilot UI 界面与交互规格

## 1. 设计目标与边界

界面名称统一使用 **EduPilot · 学业导航**。视觉关键词：可信、清晰、可追溯、校园学术感。界面必须让评委一眼看出三个核心价值：资料可管理、回答有依据、规划由规则计算。

本规格是前端界面的唯一事实来源；业务、API 和异步状态分别以 `PRODUCT_SPEC.md`、`DEMO_DATA_SPEC.md` 为准。UI 不得伪造后端数据、模型分数、文档数量或处理进度。

设计范围仅包含四个页面：

1. 首页。
2. 知识库管理。
3. RAG 问答。
4. 学业规划。

不设计登录、注册、商城、社区、消息中心、排行榜、后台运营、暗色模式或移动端原生应用。

## 2. 路由与应用框架

### 2.1 路由

```text
/            -> 首页
/knowledge   -> 知识库管理
/chat        -> RAG 问答
/planning    -> 学业规划
```

未知路由显示简洁的 404 页面，并提供“返回知识库”按钮。

### 2.2 桌面端应用框架

- 左侧导航宽 224px，固定在视口左侧。
- 顶部栏高 64px，位于内容区顶部。
- 主内容背景使用浅灰蓝，页面内边距 24px；1440px 以上使用 32px。
- 内容区最小高度为 `100vh - 64px`。
- 页面标题区与主体间距 20px，卡片间距 16px。

```text
┌───────────────┬──────────────────────────────────────────────┐
│ EduPilot      │ 页面标题 / 面包屑          后端状态 运行模式 │ 64
├───────────────┼──────────────────────────────────────────────┤
│ 首页          │                                              │
│ 知识库管理    │                                              │
│ RAG 问答      │                页面内容                      │
│ 学业规划      │                                              │
│               │                                              │
│               │                                              │
│ 数据状态卡片  │                                              │
└───────────────┴──────────────────────────────────────────────┘
      224px
```

### 2.3 左侧导航

顶部品牌区包含简洁的“书本 + 指南针”线性图标、`EduPilot` 和副标题“学业导航”。不得依赖远程图片或在线字体。

导航顺序固定：

1. 首页：`HomeFilled` 图标。
2. 知识库管理：`FolderOpened` 图标。
3. RAG 问答：`ChatDotRound` 图标。
4. 学业规划：`DataAnalysis` 图标。

当前路由使用淡蓝底、主色文字和左侧 3px 主色标记。底部显示知识库概况：可用文档数、演示数据状态；这里只展示 API 返回或由文档列表计算的数据。

### 2.4 顶部栏

- 左侧：当前页面标题及一句不超过 24 个汉字的说明。
- 右侧：后端健康状态圆点与文字、当前 Provider/设备标签（只有健康接口真实返回时才展示），以及低强调度的“演示数据均为虚构”标签。
- 后端不可达时显示固定顶部错误条，禁用写操作，保留只读页面与“重新检测”按钮。
- 后端可达但能力降级时按 `capabilities` 分别处理：documents 非 ready 时禁用上传、seed、删除和预览请求；chat 非 ready 时禁用发送；planning 非 ready 时禁用导入和计算。`unconfigured` 显示配置提示，`unavailable` 显示错误与重新检测，不得用全局 healthy 掩盖单项能力失败。
- 不显示虚构用户头像、通知数量或学校名称。

```css
:root {

  --ep-color-primary-soft: #eef3ff;

  --ep-color-evidence-soft: #ecfdf5;
  --ep-color-success: #15803d;
  --ep-color-warning: #b45309;
  --ep-color-danger: #b91c1c;
  --ep-color-info: #475569;
  --ep-color-text: #0f172a;
  --ep-color-text-secondary: #475569;
  --ep-color-text-muted: #64748b;
  --ep-color-border: #dbe3ef;
  --ep-color-border-light: #e8edf5;
  --ep-color-page: #f4f7fb;

```

主色用于主要操作和当前导航；证据色只用于引用、来源和“规则计算”标识；成功、警告、危险色遵循状态语义，不用于装饰。

### 3.2 字体与字号

不加载在线字体：

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
```

| 用途 | 字号/行高 | 字重 |
|---|---|---|
| 页面主标题 | 24/32px | 700 |
| 区块标题 | 18/26px | 600 |
| 卡片标题 | 16/24px | 600 |
| 正文 | 14/22px | 400 |
| 辅助文字 | 13/20px | 400 |
| 标签/表头 | 12/18px | 500 |
| 核心数字 | 28/36px | 700，使用等宽数字特性 |

正文不得小于 13px；表格密度不能通过缩小字体解决。

### 3.3 间距、圆角和阴影

- 间距只使用 4、8、12、16、20、24、32、40px。
- 输入框和按钮高 40px；紧凑表格操作按钮可以为 32px。
- 普通卡片圆角 12px；对话气泡 14px；弹窗 16px。
- 卡片边框 `1px solid var(--ep-color-border-light)`。
- 默认卡片不使用重阴影；悬浮层使用 `0 12px 32px rgba(15, 23, 42, 0.12)`。
- 动画时长 150–220ms；遵守 `prefers-reduced-motion`。

### 3.4 图标与插图

- 统一使用 Element Plus Icons，大小为 16、18、20 或 24px。
- 空状态使用 CSS 形状或本地图标组合，不请求远程插图。
- 图标按钮必须有 tooltip 与 `aria-label`，不能只靠图标表达删除、预览或重试。

## 4. 通用组件和状态

### 4.1 页面标题 `PageHeader`

包含标题、说明、可选状态标签和右侧主要操作。每页最多一个实心主按钮，其余使用次按钮或文本按钮。

### 4.2 状态组件

| 状态 | 表现 |
|---|---|
| loading | 首屏使用与真实布局同形的 skeleton，不用全屏旋转图标 |
| empty | 图标、明确原因、一个主要下一步；不得展示虚构统计 |
| error | 就近显示错误摘要、错误码和重试按钮；不展示堆栈 |
| disabled | 降低对比度并提供 tooltip 说明原因 |
| success | 使用短暂 `ElMessage`；关键成功结果同时保留在页面内 |
| partial | 橙色 `ElAlert`，列出成功/失败数量和“继续处理”操作 |

### 4.3 确认与反馈

- 删除使用 `ElMessageBox` 二次确认，按钮文字明确为“删除文档”，不能只写“确定”。
- demo 文档提示“仅移除运行时索引，可通过加载演示资料恢复”。
- upload 文档提示“将删除上传文件及相关索引，此操作不可撤销”。
- API 错误统一通过机器错误码映射为中文文案；服务端错误显示响应中的 request ID 供排查，纯网络失败、取消或 CORS 阻断则明确显示“未获得服务端请求编号”，不得由前端伪造。
- 任何提交按钮在请求期间进入 loading 并防止重复提交。

### 4.4 数据真实性

- 所有数量、百分比、耗时、来源和状态必须来自 API 或由真实返回值计算。
- 不允许为了界面好看写死“98% 准确率”“1,024 个文档”等数字。
- 测试 Mock 只能存在于测试文件或明确的开发 Story，不进入生产构建。

## 5. 知识库管理页面

### 5.1 页面目标

让用户在一个页面完成模拟资料初始化、上传文档、查看处理状态、预览来源和删除文档。

### 5.2 桌面布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 知识库管理                         [上传文件] [加载演示资料] │
│ 管理用于检索与学业规划的可信资料                            │
├────────────┬────────────┬────────────┬──────────────────────┤
│ 全部文档   │ 可检索     │ 处理中     │ 失败                 │
├─────────────────────────────────────────────────────────────┤
│ 搜索文件名 [来源▼] [类型▼] [状态▼]             [清除筛选] │
├─────────────────────────────────────────────────────────────┤
│ 文件名       类别     来源   类型   状态   更新时间   操作 │
│ ...                                                         │
└─────────────────────────────────────────────────────────────┘
```

顶部统计卡直接使用 `GET /api/documents` 的 `total`、`counts.retrievable`、`counts.processing`、`counts.failed`。其中“可检索”绝不能用 `counts.ready` 替代；没有数据时统计显示 `0`，不能显示占位数字。

### 5.3 演示资料初始化

前端必须建立三套互不替代的类型：Dataset `state`、Job `status`、Job document `status/result`。Job 的 `completed` 只代表达到该任务目标，绝不能直接推导 Dataset 已加载；只有重新获取 demo status 且 `loaded=true` 才能显示为可检索。

页面加载先请求 `GET /api/demo/status`，按钮与提示严格映射：

| `state` | 按钮 | 页面表现 |
|---|---|---|
| disabled | 禁用“演示资料不可用” | 展示 `reason` |
| unavailable | 禁用“演示资料不可用” | 红色错误条与检查配置提示 |
| empty | “加载演示资料” | 空库时作为主要操作 |
| queued/running | “正在加载”并禁用 | 展示进度卡并轮询 job |
| partial | “继续加载” | 展示失败数和最近任务入口 |
| loaded | 次要按钮“重新校验” | 展示版本与就绪数量；点击仍调用 seed，预期形成全 skipped 审计 job |
| failed | “重试加载” | 展示安全错误摘要 |

点击加载后：

1. 调用 `POST /api/demo/seed`。
2. 接收 202、保存 `job_id`，立即显示进度卡。
3. 优先按响应体 `poll_after_seconds` 轮询；字段缺失时固定使用 2 秒。`Retry-After` 仅作为可选兼容提示，前端不得直接读取后端环境变量。
4. 刷新页面后从 `active_job_id` 恢复轮询。
5. 终态显示 imported、resumed、skipped、failed，刷新文档列表和 demo status。

轮询网络失败时显示“正在重新连接”，采用有上限的退避重试，不得把服务端 job 改成 failed；连续三次失败后暂停自动轮询并提供“重新连接”。job 查询返回 404 时重新获取 demo status，再依据新的 `active_job_id` 或 `last_job_id` 决定展示。`completed_with_errors` 和 `failed` 的“重试”仍调用同一个 POST seed，不得发明 resume 接口。

当 `loaded=true` 且存在 queued/running 审计任务时，知识库仍可问答。`serving_previous_version=true` 时显示“新版本未就绪，当前仍使用版本 {active_dataset_version}”，不能宣称新版本已经可检索。

进度卡包含总体进度条、当前阶段、处理数量和可折叠逐文件列表。逐文件使用 `documents[].result` 和 `last_completed_stage`；绝不根据文件序号模拟进度。

不提供取消、强制重建、清空知识库或演示重置按钮。

### 5.4 上传文件

“上传文件”打开 560px 对话框：

- 支持拖拽或选择 PDF、DOCX、XLSX。
- 显示允许格式和单文件上限 50MB。
- 客户端先检查扩展名和大小，服务端仍执行最终校验。
- 文件列表显示名称、大小、等待/上传/成功/失败状态。
- 上传成功后关闭对话框并刷新列表；部分失败时保留对话框并允许逐项重试。
- 根据 `disposition` 分别反馈“已受理”“文档已存在”“已连接现有任务”“已开始恢复”。收到 `DOCUMENT_RETRY_NOT_ALLOWED` 时要求用户修正或更换文件，不得继续自动重复提交。
- 不在浏览器输出或日志中展示文件正文。

### 5.5 文档列表

默认按更新时间倒序。列定义：

| 列 | 内容 |
|---|---|
| 文件名 | 安全显示名；第二行显示文档类别或版本 |
| 来源 | `演示资料` / `用户上传` 标签 |
| 类型 | PDF / DOCX / XLSX |
| 状态 | queued、parsing、indexing、ready、failed 的中文标签 |
| 定位能力 | 页码 / 章节 / 工作表，根据类型展示 |
| 更新时间 | 本地时区的绝对时间，不使用模糊占位 |
| 操作 | 预览、查看详情、删除 |

搜索采用 300ms 防抖；来源、类型、状态筛选在前端数据量较小时本地执行。没有分页 API 时不得伪造服务端分页；文档超过 100 条后再扩展分页接口。

状态文案同时依赖处理状态与可检索字段：`retrievable=true` 才显示“可检索”；ready 且 `activation_state=candidate` 显示“已处理，待整体激活”；ready 且 `activation_state=inactive` 显示“已退役”。其余映射为：queued“等待处理”，validating/storing/parsing“解析中”，chunking/embedding/vector_indexing/keyword_indexing“索引中”，failed“失败”。列表存在非终态 upload 文档时，每 2 秒查询对应 status；全部终态或离开页面后停止轮询。

### 5.6 文档预览抽屉

右侧抽屉宽度 520px，包含：

- 文件名、来源、状态、SHA-256 前 12 位和版本。
- PDF：页码与提取文本。
- DOCX：标题路径、段落或表格文本。
- XLSX：工作表名、行范围、表头和完整行。
- 解析失败时展示错误码和恢复指引，不展示后端堆栈：demo 来源调用 seed 续跑；upload 来源让用户重新选择文件并再次调用原上传接口，后端按 `disposition` 决定续跑或拒绝，不调用不存在的 document retry 接口。不可重试错误要求用户修正或更换文件。

预览只呈现后端返回内容，禁止浏览器执行文档宏、脚本、HTML 或链接。

## 6. RAG 问答页面

### 6.1 页面目标

让用户清楚区分“模型回答”和“原文证据”，并能从引用直接查看来源位置。

### 6.2 桌面布局

```text
┌─────────────────────────────────────────────────────────────┐
│ RAG 问答                         当前可检索文档：12          │
├──────────────────────────────────┬──────────────────────────┤
│ 专业/年级/学期/文档类型筛选      │ 来源证据                 │
│                                  │ [1] 培养方案 · 第 4 页   │
│ 用户问题                         │ 原文摘录…                │
│ AI 回答，事实结论带 [1][2]       │                          │
│                                  │ [2] 考试通知 · 第 2 页   │
│                                  │ 原文摘录…                │
│                                  │                          │
├──────────────────────────────────┴──────────────────────────┤
│ 输入问题…                           [停止/发送]             │
└─────────────────────────────────────────────────────────────┘
```

主对话区最大内容宽度 820px；证据面板桌面端宽 360px。没有选中引用时显示“点击回答中的引用查看原文”，而不是虚构来源。

### 6.3 空状态与建议问题

- 无 `retrievable=true` 文档：禁用输入框，引导前往知识库加载或上传资料。
- 即使存在文档，也只有至少一项 `retrievable=true` 且 `GET /api/health` 返回 `capabilities.chat=ready` 才能发送；`unconfigured` 显示模型配置提示，`unavailable` 显示错误和“重新检测”，都不得尝试建立 SSE。
- 有可检索文档但无消息：显示 3 个基于功能类别的建议模板，例如“查询某门课程的学分要求”，不能写死不存在的具体课程事实。
- 筛选项为 `major`、`grade_year`、`semester`、`doc_category`；选项来自 `GET /api/retrieval/options`，默认折叠在“检索范围”栏，激活后显示可移除标签。前端将 `grade_year` 建模为 `number | null` 并原样提交整数，其他三项为 `string | null`；接口返回空数组时隐藏对应选择器，不硬编码选项。

### 6.4 消息样式

- 用户消息右对齐，使用主色浅背景，最大宽度 72%。
- 助手消息左对齐，白色卡片，最大宽度 86%，顶部标记“基于知识库”。
- `[1]`、`[2]` 引用渲染为证据色按钮，键盘可聚焦；点击后选中右侧证据卡。
- Markdown 渲染禁止原始 HTML，链接默认不自动打开；外部链接必须再次确认。
- 流式输出使用细小光标，不使用大面积闪烁 skeleton。

### 6.5 SSE 状态流

严格处理 `token`、`citation`、`done`、`error`：

- `token`：追加文本，不根据模型文本自行生成引用。
- `citation`：按 `citation_index` 建立引用卡；正文引用尚未到达时保留占位映射。
- `done`：停止流式状态，显示复制回答和检索详情入口。
- `error`：保留已收到的部分内容，标记“回答中断”，显示重试按钮。

因为接口为 POST，前端使用 `fetch + ReadableStream + TextDecoder + SSE parser`，不能使用只支持 GET 的原生 `EventSource`。网络 chunk 不能被当作完整 SSE 事件或完整 UTF-8 字符；无 `done/error` 就 EOF 时标记为“连接中断”，不得当作成功，也不得自动重复提交问题。

用户手动向上滚动后暂停自动跟随；只有用户仍接近底部时才随 token 滚动。`done.outcome=refused` 使用中性拒答卡，`conflict` 使用警告卡，两者都不是网络错误。

生成期间发送按钮变为“停止”，客户端中止连接后恢复输入状态。停止不等同于错误，不弹红色提示。

### 6.6 证据面板

证据卡必须展示：引用编号、文件名、页码或工作表、章节、行范围和 quote。缺失字段不显示空标签。点击“查看原文”调用 `/api/sources/{chunk_id}` 并打开来源抽屉，定位到对应页、章节或行。

无证据拒答使用中性提示卡：“当前知识库没有足够依据”，提供“调整检索范围”和“前往知识库”操作，不使用危险红色。

冲突回答使用警告卡并并列展示来源版本，禁止在 UI 中自动隐藏旧版本或替用户选定结论。

## 7. 学业规划页面

### 7.1 页面目标

突出“规则引擎计算，不由大模型心算”，让学分差距、缺失必修课、类别缺口和证据清晰可核验。

### 7.2 桌面布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 学业规划                 [导入培养规则] [导入课程记录] [计算]│

│ 要求学分  │ 已修学分  │ 在修学分  │ 剩余学分                │
```

### 7.3 初始与导入状态

- 页面进入先调用 `GET /api/academic/options`，分别显示课程记录集和培养方案版本选择器。
- 只有一个 ready 选项时可以预选；存在多个选项时必须由用户明确选择，不能静默选择“最新版本”。
- 选择写入 URL query 的 `record_set_id`、`rule_set_id`，刷新后先验证这些 ID 仍在 options 中；无效时清除选择并提示。
- 未导入规则：显示“先导入培养方案规则”。
- 未导入课程记录：显示“导入匿名课程记录以计算学分”。
- 两者齐全后启用“开始计算”。
- 导入对话框复用上传组件，但分别调用 academic records/rules API，不能混入普通知识库上传请求。
- 不在页面示例中出现真实姓名或学号。
- 点击计算只提交 `{ record_set_id, rule_set_id }`，展示服务端 `PlanningResult`，不得在浏览器重新计算学分。

### 7.4 规划结果

顶部四个数字卡严格绑定 `PlanningResult`：

- `required_credits`
- `completed_credits`
- `in_progress_credits`
- `remaining_credits`

数字卡下显示一条组合进度条：已修为主色、在修为浅蓝、剩余为灰色。宽度只按 Product Spec 的数值不变量做展示归一化：已修段先封顶于 required，在修段封顶于剩余空间，剩余段补足至 required。`completed + in_progress > required` 时视觉宽度封顶 100%，保留真实数字并显示“已超过要求”，不得误报为数据错误；字段为负数或 required 为 0 且存在非零进度时才显示数据错误。客户端不得借此修改服务端结果。

类别缺口使用横向进度条和文本数值，不引入额外图表库。缺失必修课使用表格，移动端转换为卡片。不得允许直接编辑规则引擎输出。

### 7.5 冲突与证据

- `conflict_warnings` 置于右侧警告区，按规则版本、课程重复、课表冲突分类。
- 没有冲突时显示绿色简短状态“未发现规则冲突”，不显示虚构建议。
- `evidence` 使用与 RAG 相同的来源卡和抽屉组件。
- 页面固定显示“结果由确定性规则引擎计算；AI 仅负责解释”的证据色标签。
- 重新计算覆盖当前展示前必须保留 loading 状态，失败时继续显示上一次成功结果并注明未更新。

## 8. 首页（Home）

### 8.1 页面目标

首页是 `/` 的落地页，让评委与用户在首屏内理解“资料可管理、回答有依据、规划由规则计算”，并提供进入三项能力的明确入口。

### 8.2 布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 校园多源文档 RAG 学业规划助手                                │
│ 用可信资料，回答学业问题                                     │
│ 一句话说明                       [进入知识库] [查看学业规划] │
├───────────────────────────────┬─────────────────────────────┤
│ 可检索文档 15 / 共 15         │ 后端连接 · 运行模式          │
├───────────────────┬───────────┬─────────────────────────────┤
│ 知识库管理        │ RAG 问答  │ 学业规划                    │
│ 状态标签          │ 状态标签  │ 状态标签                    │
│ 说明文字          │ 说明文字  │ 说明文字                    │
│ 打开知识库 →      │ 开始问答 →│ 查看规划 →                  │
└───────────────────┴───────────┴─────────────────────────────┘
```

- 首屏最多一个实心主按钮（“进入知识库”）；“查看学业规划”与三张卡片的入口使用次要/文本样式。
- 三张能力卡片顺序与主导航一致，分别链接到 `/knowledge`、`/chat`、`/planning`。
- 卡片状态直接取 `GET /api/health` 的 `capabilities`，使用“可用 / 未配置 / 不可用”三态文案，不得写成“故障”。

### 8.3 动效

- 背景为轻量渐变光斑与 SVG 连线的缓慢漂移，只动画 `transform` / `opacity`，周期不小于 18s，避免闪烁与持续高负载。
- 内容入场为一次性淡入上移，时长 220ms，允许多元素按不超过 60ms 的步进延迟。
- 功能卡片悬停/键盘聚焦时上浮 2px 并显示悬浮阴影，过渡 180ms。
- 所有动效在 `prefers-reduced-motion: reduce` 下一律关闭（含延迟），只保留静态呈现。
- 动效不请求远程图片、在线字体，也不新增动画库。

### 8.4 数据真实性

- 资料数量只来自现有 `documents` store（`total`、`counts.retrievable`）；未就绪或读取失败时显示文字说明或占位符，绝不编造数字。
- 后端连接状态与运行模式来自现有 `health` store，运行模式标签只在健康接口真实返回后展示。
- 首页不发起任何网络请求；加载由应用框架统一负责，避免重复拉取。

### 8.5 响应式与可访问性

- 1200px 以上三列卡片；768–1199px 两列；小于 768px 单列，且入口按钮最小 44px。
- 背景图层 `aria-hidden="true"` 且 `pointer-events: none`，不进入焦点顺序。
- 卡片入口为真实链接，键盘可聚焦并有可见焦点环；对比度遵守“可访问性与安全”一节。

## 9. 响应式行为

| 宽度 | 行为 |
|---|---|
| ≥1200px | 224px 完整侧栏，双栏内容，证据面板常驻 |
| 768–1199px | 72px 图标侧栏；统计卡两列；证据面板改为右侧抽屉 |
| <768px | 顶部菜单按钮 + 导航抽屉；卡片单列；表格转卡片或允许局部横向滚动 |

移动端内容边距 16px。底部输入框不能被软键盘遮挡。知识库和规划页的主要操作放入标题下方，不挤压标题。最低验收视口为 390×844、1024×768、1440×900。

## 10. 可访问性与安全

- 目标为 WCAG 2.2 AA；正文与背景满足对比度，状态不能只依靠颜色表达。
- 应用壳第一个可聚焦元素为“跳到主要内容”，当前导航设置 `aria-current="page"`。
- 所有操作可通过键盘完成，焦点顺序与视觉顺序一致。
- 可点击目标最小 40×40px，移动端最小 44×44px。
- 使用可见焦点环；弹窗/抽屉打开后正确管理焦点，关闭后返回触发按钮。
- 表单控件拥有可见 label，错误信息通过 `aria-describedby` 关联。
- 进度条提供 `aria-valuemin`、`aria-valuemax`、`aria-valuenow`；进度变化使用 `aria-live=polite`，流式 token 不逐字朗读，完成后再通知。
- 文档 quote 按纯文本处理；禁止 `v-html` 直接渲染后端或模型内容。
- 文件名和错误消息经过转义，不显示绝对路径、密钥或堆栈。

## 12. 测试与验收

### 12.1 单元与组件测试

- demo 的 8 种聚合状态分别映射到正确按钮、文案和可用性。
- Dataset、Job、Job document 三套状态不能混用；job completed 后必须重新读取 status 才能判断 loaded。
- 轮询重复进入不会产生两个 timer；终态或组件卸载后停止轮询。
- SSE 网络分片、跨 chunk 中文字符、四种事件、用户停止、无终止 EOF、流中断和引用乱序均有测试。
- 规划数字直接来自 `PlanningResult`，不得在组件中二次计算业务结果。
- upload/demo 删除确认文案与来源类型一致。
- 所有 error、empty、loading、disabled、partial 状态有显式测试。

### 12.2 Playwright 场景

1. 空知识库 → 加载演示资料 → 刷新恢复 job → 完成后文档可见。
2. 重复加载 → 全部 skipped → 不产生重复行。
3. 上传三种文件 → 查看状态 → 打开不同定位类型预览。
4. 正常问答 → 流式回答 → 点击引用 → 查看原文定位。
5. 无依据问题 → 明确拒答且不出现虚构引用。
6. 导入规则与课程记录 → 计算 → 校验四个学分数字、缺失课程和证据。
7. 后端离线、API 超时和单文件失败时界面不崩溃并提供恢复操作。
8. 在 390×844、1024×768、1440×900 下无整页横向溢出，核心操作可达。

### 12.3 视觉验收

- 四个页面共享同一导航、标题、Token 和状态语言。
- 页面首屏只存在一个主操作，层级清楚。
- 引用/证据始终使用证据色，与普通按钮可区分。
- 不出现远程字体失败、占位头像、假图表、随机统计或模板化营销文案。
- 1440×900 下知识库表格、问答证据面板和规划核心结果无需整页滚动即可看到主要内容。
- 浏览器缩放 200% 后仍可操作，无文字遮挡。
- Playwright 运行期间没有未处理的控制台错误，关键流程可以只用键盘完成。

阶段 8 只有在 Vitest、Playwright、前端构建以及上述状态/视口验收实际通过后才能完成。
